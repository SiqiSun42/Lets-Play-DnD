# 规则检索（`search_rules`）

**需要规则细节时才读这一份**。三处可能会用到：

| 场景 | 为什么要查 |
|---|---|
| 元对话 | 玩家问规则，例如法术怎么结算、某操作是否允许 |
| 属性检定 | 需要 DC、判定属性/技能、以及成功与失败的界线 |
| 游戏动作 | 确认这个动作在本规则下是否成立、怎么结算 |

## 为什么要改写

把玩家原话直接丢进去，命中率低。要提取**核心概念**，整理成关键词。

- 「那么，我现在就要施展火球术！」→ 提取「火球术」，**不要**整句
- 「我很喜欢星球大战中的尤达大师，我能否在 DnD 中创建一个类似的角色？」
  → 提取**与 DnD 相关的概念**（本例：长寿、睿智、能力强大的非人类角色），不要照搬原话

## 查询格式

- 每次查询用 **1 到 3、4 个 DnD 专业术语**，彼此补充或关联。
  例如「火球术 豁免 伤害」，或「半兽人 寿命」
- `context_label` 用一句自然语言说明这次查什么，例如「火球术的豁免与伤害」。
  这个标签**不参与搜索**，只是随结果一起返回，用来标明结果属于哪次查询

## 多次查询

- 输入含多个概念时**分别查，不要合并**。
  例如「法师和术士的施法过程有什么区别？」→ 分查「法师 施法过程」和「术士 施法过程」。
  合并成一次的话，命中的很可能是同时提到两者、却说不清区别的段落
- 不确定单次还是多次时，**默认多次**。也可以换关键词重复查同一件事
  （例如同时查「长寿物种 强大」和「长寿物种 睿智」）
- **总次数不超过三次**，否则返回信息过多反而难以处理

## 什么时候不要查

查询是有代价的：每一次都要等检索返回，而且塞进过多片段反而干扰判断。

- 规则无关紧要、或**光靠常识就能确定**的小事 → 不查
- 玩家只是在闲聊、寒暄、推进剧情 → 不查
- 本回合**已经查过**的内容 → 不重复查
- 差一点点信息就够用 → 不查，按常识走

**查不到就用常识回答，并如实说明**「按常见 5e 理解是……，以你们桌规为准」——
你引用的每一句，都要能在查到的片段里找到。

## 拿到结果之后

- **有片段：以片段为准。** 片段是你唯一可以引用的规则来源，其中的具体数值就是最终数值
- **片段与玩家的问题不相关**：当作没查到处理，走上面的常识路径
- 数值、修正值、DC 来自片段或本回合读到的面板
