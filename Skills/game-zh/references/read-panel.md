# ① 读：本回合要看什么

先看清存档里有什么，再决定读什么。**这一步的产出是本回合唯一可信的事实来源**——
后面所有阶段（判类、生成、更新）都只能用这里读到（或本回合写进去）的值。

## 先列目录

用 `list_dir` 看当前工作区，确认有哪些文件与地点文档。
**它已经在你的工作目录里**，只要给相对路径，不用也不能指定根：

```
list_dir()                     # 工作目录本身（也就是存档的 data/）
list_dir("world")              # 某个子目录
list_dir("status/allies")
```

`list_dir` 的上界是**你的工作目录**：`..` 也出不去，看不到存档文件夹、别的存档、账号目录。
这不是限制，是设计——再往外的内容（规则、技能说明）都是以 skill 形式只读传入的，
本来就不需要你去翻。文件名拿到之后用 `read` 读内容。

## 默认集：每回合都要读

这四个**每回合都读**——它们几乎每回合都在变：

| 文件 | 为什么要 |
|---|---|
| `current_info.json` | 当前时间、地点、玩家角色——它们几乎每回合都变 |
| `plot/cur_main_plot.md` | 主线骨架：剧情在它的范围内展开 |
| `world/<current_location>.md` | 当前场景（文件名取自 `current_info.json` 的 `current_location`） |
| `characters/allies/*.md` | 同行角色的人物设定。有几个读几个 |

## 按需集：本回合用得到才读

| 触发条件 | 读什么 |
|---|---|
| 涉及背包、金钱、装备 | `inventory.md` |
| 玩家移动，或要判断地点关系 | `world/map.json`，以及相关 `world/<地点>.md` |
| 涉及 HP、法术位、状态效果、队友当前状态 | `status/allies/<角色>.md` |
| 涉及敌人 | `status/enemies/<敌人>.md` |
| 涉及规则细节 | 先走规则检索（③ 阶段） |

**不确定要不要读的，就先读。** 多读一次只是花一点上下文；
读漏了会导致本回合基于错误状态推进，而且**不会报错**。

## 怎么读

- 用 `read` 工具，路径相对工作区；一次可以并行发多个 `read`（它们互不依赖）
- 文件不存在就是不存在：读不到的内容，就当它不存在
- 读到的内容会留在对话历史里，但**更早回合读到的旧版本一律不作数**：
  需要某个值时，必须是**本回合**读到的（或本回合自己写进去的）。
  这条规则同时写在 `SKILL.md` 的全局不变量里。

## 漏读了怎么办

**不用回头重来。** ③ 生成过程中如果发现还缺某个文件，**直接补读再继续**——
只要遵守那条不变量（本回合读到或写过的值才算数），中途补读完全合规。

默认集仍然每回合都要读：漏了它，写出来的内容多半会和设定冲突，而你未必当场发现。

## 常见错误

| 错误 | 后果 |
|---|---|
| 靠上一回合的印象填数值 | 面板一直在变，你会拿到过期状态，而且**不会报错** |
| 只读 `current_info.json` 就开写 | 当前场景文档与人物设定缺失，叙述会与设定冲突 |
| 到了新地点却不读 `world/map.json` | 无法判断新地点该挂在哪个父节点下 |
| 玩家要用道具却不读 `inventory.md` | 可能描述出并不存在的物品 |
