# ③ 生成：属性检定

本回合类别已确定为**属性检定**：玩家意图触发一次（或明确指向）属性/技能/豁免检定，
重点在「是否成功」的判定。

输出分三段：**开场 → 计算 → 结果**。下面先说判据与数值从哪来，再说格式。

## 初步判断

先简单判断玩家的输入是不是游戏内合规动作、能不能在本回合正常推进。

如果不合规（例如玩家当前处于某些特殊状态，无法执行检定），**不做检定**，直接输出对玩家的提醒或指导即可。

## 数值从哪来

需要什么读什么，不要一次读所有人：


| 需要                                         | 读                                                                                                                                            |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **行动者的状态**（HP、属性、熟练、状态效果） | `status/` 下**这个行动者**的文件。玩家自己行动 → 读玩家角色（名字见 `current_info.json` 的 `current_player`）；让 NPC 队友行动 → 读那个队友 |
| 玩家要用某件道具                             | `inventory.md`                                                                                                                                |
| 环境、地点相关                               | 当前地点文档                                                                                                                                  |
| 规则细节                                     | 先读`references/rule-query.md` 再调 `search_rules`                                                                                            |

**数值只从本回合读到的面板与规则摘录里取。**
面板里没有给出的修正就是没有——不要凭空补一个，也不要凭记忆填。

## 检定规则

### DC（困难等级）

根据当前场景的描述难度选 DC。没有明确信息、或无法确定时，用默认值 **DC 12**。


| DC   | 难度         |
| ---- | ------------ |
| < 10 | 简单         |
| 12   | 中等（默认） |
| > 15 | 困难         |

### 属性与技能

根据动作判定所用属性；玩家已点明属性或技能时，从其指定。常见对应：


| 属性 | 常见技能               |
| ---- | ---------------------- |
| 力量 | 蛮力、运动             |
| 敏捷 | 杂技、隐匿、巧手       |
| 体质 | 忍耐、专注维持         |
| 智力 | 调查、自然、宗教、奥秘 |
| 感知 | 察觉、医疗、求生、洞悉 |
| 魅力 | 欺瞒、威吓、表演、说服 |

### 要不要查规则

**简单的检定通常不用查**——判断检定种类、投一个 d20、加修正、比较 DC 就够了。

但**任何一步拿不准都可以去查**：不确定这个动作该用哪个属性、不确定某个状态有没有影响、不确定某条规则怎么算，就先读 `references/rule-query.md` 再调 `search_rules`，按返回的片段调整。查不到就按常见 5e 理解处理，并如实说明。

### 骰子

需要骰值时调用 `roll_dice`，**通常就是一个 d20**。

**正文里出现的每个数值都要有来源**：骰值来自 `roll_dice`，修正值来自面板或规则摘录。

## 输出格式

### 第一段：开场

简洁生动地把玩家意图写成检定发生前的场景，用**第二人称**、以「你」起笔，让玩家感到角色正在尝试这个行动。

### 第二段：计算

用引用块写出这一步怎么算的，每个数值都标注来源：

```
> 14（敏捷检定骰，1d20）+ 2（熟练加值）+ 3（敏捷调整值）= 19 ≥ 15（DC）
> 结果：成功
```

- 骰子要写来源与面数，例如 `13（敏捷检定骰，1d20）`；多颗同面骰可写 `(3+4)（相关骰，2d6）`
- 其他数值同样标注，例如 `2（熟练加值）`、`12（DC）`
- 有多个不同的运算步骤时，可以写多组
- **检定总值 = 骰子结果 + 全部适用修正**

### 第三段：结果

把检定结果写成场景，语气贴合下面的结果光谱，**几句话到一两段**。如果是对话交互、打听信息（且成功），可以稍长；而动作只需要覆盖检定的结果即可。

#### 结果光谱

依据**骰面**与**总值相对 DC** 选档位：


| 档位         | 条件                    | 写法                                                                                                                 |
| ------------ | ----------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **极端成功** | 骰子为 20               | 远超预期的成功。很罕见，可带一点额外的趣味效果或幽默                                                                 |
| **成功**     | 总值 ≥ DC，且非 20     | 按预期成功。超出 DC 越多越轻松；刚好等于 DC 则显得艰难或惊险                                                         |
| **失败**     | 总值 < DC，且骰子不是 1 | 低于 DC 越多后果越糟；非常低（但不是 1）可带轻微负面效果。非常接近 DC 属于「功亏一篑」，某些情况下也可实现小部分目标 |
| **极端失败** | 骰子为 1                | 灾难性的失败。很罕见，可带一点趣味式后果或幽默                                                                       |

### 可选的 DM 附注（规则层面的结论）

**正文负责沉浸感，这里负责把规则层面的结论标准地讲清楚。**

若本回合有生效的规则结论，用一两句加一条引用块附注：

```
> 由于敏捷豁免失败，你没能躲开陷阱，陷入束缚状态。
```

- **要列的**：获得或解除的状态、豁免的结论、以及正文传达不到的规则性变化
- 不要写成场景描写——场景描写属于第三段
- 本回合没有规则层面的结论，就不写这一条

## 完整例子

以下仅供理解流程，勿照搬措辞。假设玩家输入：「我在半兽人洞穴里潜行，想绕过门口的哨兵。」

### 成功（本回合输出的样子）

```text
你压低呼吸，贴着潮湿的岩壁朝洞口挪过去。火把光在石壁上摇晃，哨兵的背影就在几步之外。

> 14（敏捷检定骰，1d20）+ 2（熟练加值）+ 3（敏捷调整值）= 19 ≥ 15（DC）
> 结果：成功

你踩过碎石时几乎没有声响，哨兵只是揉了揉鼻子，仍盯着洞外。你从阴影里滑了过去，完全没被发现。
```

本例没有对应的状态或术语，所以不加 DM 附注。

### 失败（含可选附注的样子）

```text
你压低呼吸，贴着潮湿的岩壁朝洞口挪过去。火把光在石壁上摇晃，哨兵的背影就在几步之外。

> 4（敏捷检定骰，1d20）+ 2（熟练加值）+ 3（敏捷调整值）= 9 < 15（DC）
> 结果：失败

一不小心，你的靴底蹭到一块松动的石子，咔哒一声在洞里回荡。哨兵猛地转身，火把晃向你这边。你被发现了！

> 哨兵已经警觉，你的潜行优势消失了。
```

## 注意事项

- **只写到这一检定对应的具体事件是成功还是失败**（本例：能否隐秘地通过而不被发现）。
- 成功就到此为止，不要继续写洞穴以后的事件；失败也不要在本回合展开互砍、扣血或其他有实质伤害的交战。
  那些属于后续回合。
- 对其他类型的检定同理：**后果留给后续回合处理。**
- 上述例子仅供参考，实际的结果描述可以更为详细、生动。
