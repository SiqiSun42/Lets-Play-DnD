# ④ 更新：地点与地图

只处理 `world/<地点>.md` 与 `world/map.json`。通常涉及两类任务，可能只出现其一，也可能同时需要：

1. **新地点**——当前地点在目录里还不存在，要创建文档并挂进地图
2. **更新旧地点**——对已有的 `world/<地点>.md` 按本回合结果补充或修订

**不要动**背包、状态、人物设定，也不要写 `current_info.json`——
地点写完**之后**，由 `references/update/plan.md` 的「时间与地点」负责把它写进去。

## 只看本回合已经发生的

只根据**本回合已经发生、并且已经写进正文或附注**的结果来改。不要预支下一回合，
不要凭空发明。

## 怎么改

1. 先用 `read` 读要改的文件（`world/map.json` 与相关地点文档）——覆盖之前必须先读
2. 新文档用 `write` 创建；对已有内容用 `edit` 做精确替换
3. `edit` 的 `old_string` 要与原文**精确匹配**，且不能同时匹配多处；片段尽量短而唯一
4. **改 JSON 时必须保持合法**：不能有注释，不能有尾逗号

不产出给玩家看的文字。

# 一、新地点

## 建档内容

新建的地点文档保持简洁，**必须且只能**包含两项：

1. **地理位置**：与上级、同级、下级（如有）的关系，或如何从此处回到已知地点
2. **环境描述**：一两句自然氛围即可

人物、物品、事件等本回合正文尚未明确成立的内容，不要编造；留给后续探索再补充。

## 地图挂载（`world/map.json`）

把新地点挂到合理层级。地图是**三层嵌套**，子地点写在父节点的 `layer_2` / `layer_3` 数组里。

**禁止**使用 `children` 字段，也**不要**添加 `layer_guide` 或其他说明字段。

层级含义：

| 层 | 是什么 | 例子 |
|---|---|---|
| `layer_1` | 较大区域 | 城市、小镇、村庄、开阔的平原/树林 |
| `layer_2` | 场所（建筑或有明确功能的小区域），挂在某个 `layer_1` 下 | 酒馆、旅店、城堡、码头、山洞 |
| `layer_3` | 封闭小空间，挂在某个 `layer_2` 下，不可再往下拆 | 房间、石室 |

格式示例（占位符）：

```json
{
  "layer_1": [
    {
      "id": "地点1，城镇、村庄、森林等",
      "layer_2": [
        {
          "id": "地点2，旅馆、码头、小巷、山洞等",
          "layer_3": [
            { "id": "地点3，房间、走廊、小洞穴等" }
          ]
        }
      ]
    }
  ]
}
```

- 若「地点2」暂无下层，可省略 `layer_3`；若「地点1」暂无下层，可省略 `layer_2`
- 每个节点至少有 `"id"`
- **`id` 必须与 `world/<地点>.md` 的文件名（去掉 `.md`）逐字一致**

## 建档要一次做完

创建地点文档 **和** 更新 `world/map.json` 是同一件事的两半，不要只做一半——
地图里没有它，或文档不存在，都会让后续回合找不到这个地方。

文件名（不含路径与后缀）应与地图里的 `id` 一致；而这个文件名随后会被写进
`current_info.json` 的 `current_location`（见 `references/update/plan.md`），所以**别取完名又改**。

# 二、更新旧地点

对目录里已有的地点文档，根据本回合的探索或互动结果补充或修订。

地点文档除地理位置、环境描述之外，通常还可能包含以下信息（按顺序）。
**若某类信息本来就不存在、且本回合也没出现，不要添加空标题。**

## 人物

分两类：

- **常驻人物**：所有常驻此地、且随时能在此找到的可互动人物（酒保、店老板……）。
  简单记录姓名、种族、外貌之类的相关信息；同一地点可以记多个
- **背景人物**：喝酒的群众、渔民、来来往往的客户……通常不可互动的背景角色

**常驻人物的判定**：只把本回合正文中**已明确出场**、且适合长期互动的角色记为常驻。
必须具备以下之一：

1. 有明确的职业功能性，能为玩家提供服务（店长、酒保）
2. 与主线或支线剧情**直接**关联（公主、海盗头子）

判断标准就是：**没有这个角色，玩家就无法正常游戏**。否则都只是普通 NPC。

## 物品与资源

一般只在商店、旅馆、铁匠铺这类能购买物品或服务的地方记录，用表格：

```markdown
| 物品/服务名称 | 描述 | 单价 |
|---|---|---|
```

## 事件记录

**只记录对地点造成永久改变的大事件**——酒馆被焚毁、雕像倒塌。
广场上有人打架这类小事不记。

## 补写的位置

如果当前文件里没有某类信息（比如没有事件），而本回合发生了，就在对应位置**写入标题**
（例如 `# 事件`），再写具体内容。人物、物品与资源同理。

也可以视情况修订地理位置或环境描述。本回合若涉及多个已有地点的变化，分别改。

---

# 注意

- 未在本回合正文或附注中成立的变化，不要写入
- 三处最容易出错的：**`map.json` 里用了 `children`**、**`id` 与文件名不一致**、
  **只建档忘了挂地图**（或反过来）
