# ④ 更新：把本回合的变化落盘

这一阶段做三件事，都发生在幕后：

1. **先枚举**——本回合有哪些数据变了（先列出来，见下）
2. **逐条落盘**——把每一项写进对应的面板文件
3. **对账**——检查面板与本回合实际发生的事有没有对不上

这一阶段**不产出给玩家看的内容**：不说叙事，不解释。

## 判断依据只有一条

**只根据本回合已经发生、并且已经写进正文或附注的结果来判断。不要预支下一回合。**

这句话也定了**顺序**：**正文先产出，落盘在后面。** 照着正文与附注里写过的改；
不要在正文之前就动手改存档——那样账本会先于玩家读到的故事，依据也变成"我准备做什么"。

清单上的每一项，都应该能在本回合的**正文或附注**里找到对应；两处都没有的，不要出现在清单上。

## 第一步：先枚举

进入落盘之前，先把本回合需要更新的内容**列出来**，写在你的思考里。每项写成「对象：旧值 → 新值」：

```
面包：3 → 2
HP：20 → 15
时间：下午 → 傍晚
地点：旧城广场 → 东侧窄巷
```

- 数据确实发生变化时才列；没有变化就不列
- 旧值取你本回合读到的值（没读到旧值就只写新值，例如新获得的物品）
- 一时性的东西（一句说完就过的对话、短暂的表情）不进清单
- 写在思考里就好，**不要混进正文**——正文是给玩家的故事，不该在里面念账本

> 思考区域玩家是看得到的（前端会单独显示），这里没有"藏起来"一说。
> 要守的界线只有一条：**账本别混进正文**。

**为什么必须先枚举**：漏改一项，后续回合就会一直在错的状态上推进，而且不会报错。
列出来、改一条划一条，是最省事的防漏办法。

### 各类回合常见的变化

最容易漏的，是"这类回合看上去不像要改面板"。按类别对一眼：

| 本回合类别 | 常见变更 |
|---|---|
| 游戏动作 | 最常改：背包（喝药水、消耗、捡到）、状态（HP / 法术位 / 状态效果）、地点（移动）、人物（同伴关系持久变化） |
| 属性检定 | 通常没有；出现了**持久**的状态变化（被束缚、中毒、消耗法术位）或物品得失才落 |
| 角色互动 | 通常没有；人物设定 / 关系发生**持久**变化、物品得失才落 |
| 环境探索 | 通常没有；**移动**了才改时间与地点 |
| 元对话 | 通常没有；唯一例外是玩家**纠正了某个写错的值**（「我的 HP 应该是 12」），按纠正后的值改对 |

一时性的东西（一句说完就过的对话、短暂的情绪）一律不进清单。

## 这些变化要不要写给玩家看

分三种，别一锅端：

| 类型 | 怎么给玩家看 | 例子 |
|---|---|---|
| **判定过程** | 计算块（可复核） | 骰子 + 修正 vs DC |
| **重要的规则类变化** | **DM 附注里标准列出** | HP / 法术位 / 生命骰恢复、获得或解除状态 |
| **不言自明的变化** | 不用单列，正文带到即可 | 药水少一瓶、穿上铠甲、换武器 |

- **正文负责沉浸感，DM 附注负责把规则层面的变化讲清楚。**
  「你睡醒了觉得神清气爽」不能代替「生命值完全恢复，法术位重置」——那句话必须明确写出来。
- 但药水少了一瓶、换装备这类**不言自明**的，正文提到就够了，不需要专门说明。

你在这里枚举，是为了**自己不漏改文件**；给玩家看的是其中**规则层面**的那部分（走 DM 附注）。

## 每一项落到哪个文件

| 清单里的对象 | 写进 | 细读 |
|---|---|---|
| 时间、当前地点 | `current_info.json` | 本文档下方「时间与地点」 |
| 背包、金钱、装备栏、负重 | `inventory.md` | `references/update/inventory.md` |
| HP、法术位、状态效果 | `status/allies/<角色>.md` | `references/update/status.md` |
| 人物设定、性格、动机、关系 | `characters/allies/<角色>.md` | `references/update/characters.md` |
| 地点文档、地图 | `world/<地点>.md`、`world/map.json` | `references/update/location.md` |

## 联动：一次要改多处的情况

有几条规则**跨文件**。遇到这些，**先把要改的地方一次想全，再动手**——
改了一半是最容易留下的坑。

| 情况 | 要一起改 |
|---|---|
| **穿脱装备**（铠甲、武器） | `inventory.md` 的装备表「是否装备」（新装备还要改负重）＋ `status` 的装备表、AC、属性修正。**两边必须一致** |
| **体能值变化** | `status` 里的体能值 ＋ `inventory.md` 的**最大负重**（最大负重是按体能值算的） |
| **关系变化** | 如果 `characters` 里两边都写了这段关系（例如玩家角色的档案里也写了），两处都要改 |

## 执行顺序

1. **先处理会新建文件的**：地点（新建 `world/<地点>.md`、挂进 `world/map.json`）
2. 再处理普通面板：`inventory.md`、`status/…`、`characters/…`
3. **最后写 `current_info.json`**（时间与地点）

地点放到最后，是因为 `current_location` 必须与**实际建出来的文件名**一致——
先建档、再回头用真实文件名写进去，名字就不会错位。

## 时间与地点

这两项直接写 `current_info.json`（前端的地点面板读它的 `current_location`）。

### 地点：名字必须与文件名逐字一致

玩家位置变化时，写**到达后**的地点名称（不含 `.md`）。

**这个名字必须与 `world/` 下实际存在的文件名逐字相同。** 前端是拿 `current_location`
去取 `world/<名字>.md` 的——差一个字就取不到，地点面板会**空白，而且不报错**。

- 到达**已有**地点：名称照抄 `world/` 下的文件名（去掉 `.md`），不要凭印象写
- 到达**新地点**：先按 `references/update/location.md` 建好文档，**再回头用你实际建出来的那个
  文件名**写进 `current_location`；拿不准就 `list_dir("world")` 看一眼真实文件名
- 没有移动就保持原值

### 时间

时间发生变化（推进或修正）时，写更新后的**完整**时间字符串，例如「冒险第一天 晚上」。
格式一般是「冒险第x天」+「清晨 / 上午 / 中午 / 下午 / 傍晚 / 晚上 / 深夜 / 凌晨」。
没有变化就保持原值。

## 什么时候地点文档也要跟着改

不只是"到了新地方"。以下情况也值得更新 `world/<地点>.md`：

- 在商店 / 铁匠铺 / 酒馆之类的地方了解到**新的物资或服务**（本店提供药水、面包、住宿，而文档里还没有记）
- 认识了此地的功能性常驻 NPC（酒保、店长、老板……此前文档里没提过）
- 本地外观发生**重大或永久性**变化（被烧毁、被封路）

仍在原地、也没发生上述情况时，地点文档不必动。

## 落盘怎么做

1. 用 `read` 读目标文件的**当前**内容（覆盖前必须先读）
2. 用 `edit` 改（改动小的时候）或用 `write` 整体重写（改动大、或就是新建文件）
3. 改完一条，回到清单划掉一条

**逐条改完要回清单核对**——漏掉的那项会在后续回合里一直错下去。

## 对账

改完之后，检查一遍清单与面板：

- **清单上写了、面板里没变** → 立刻补上
- **面板里变了、清单上没写** → 说明是你手动改的，回头在清单里补记（或者改回去）

判断依据是**清单与面板的不一致**，不是"你觉得应该是什么"。
凭印象去覆盖一个本来正确的面板，比漏改更糟。

## 本流程不处理战斗

如果正文停在「战斗一触即发」，**本回合到此为止**——战斗初始化是紧接着的独立流程，本流程不做。
所以清单里没有战斗相关的项。
